# LT6911C HDMI to MIPI CSI Converter Subsystem

# Description
The [LT6911C](https://github.com/HynixCJR/serverv2_backplane/blob/main/datasheets/LT6911C_HDMI_to_CSI_system/LT6911C_HDMI_to_CSI_datasheet.pdf) is an HDMI 1.4 to MIPI CSI converter IC. In the LAZARUS-1 Backplane PCB, it is used to convert the HDMI signal from the PS176 (whose video signal originates from the connected host device) to a MIPI CSI signal that can be interpreted by the LicheeRV Nano. The LicheeRV Nano can use this display signal to enable IPKVM capabilities.

Unfortunately, the LT6911C is not very well documented, with only proprietary firmware options. Furthermore, there are no official reference designs or schematics, and the (leaked) datasheet is quite barebones. So, the design of the LT6911C circuit used on this PCB is largely reverse engineered from the publicly released [3D model](https://github.com/HynixCJR/serverv2_backplane/blob/main/datasheets/LT6911C_HDMI_to_CSI_system/LT6911C_Sipeed_3D_model.html) of the official adapter HDMI->CSI adapter board used in Sipeed's NanoKVM Lite. Modifications were made to this design using (generally) cheaper components and to adapt it to the embedded architecture of the Backplane PCB. This was all cross-referenced with an open source [LT6911C HDMI->MIPI DSI board](https://github.com/HynixCJR/serverv2_backplane/blob/main/datasheets/LT6911C_HDMI_to_CSI_system/LT6911C_HDMI_to_DSI_reference_schematic.pdf) designed by Hyper12 on [OSHWHub](https://oshwhub.com/cnflysky/h2d_lt6911c). Unfortunately, this is implemented for DSI rather than MIPI CSI, so an exact copy wasn't possible.

The design very closely mirrors the official HDMI->CSI adapter used in the NanoKVM Lite, as the NanoKVM's binary file for this adapter is unfortunately the only way to use the LT6911C for this purpose without a license.

# Design

### Power
There are three voltage rails used in this design: 3.3V, 1.8V, and 1.2V. The 3.3V and 1.2V rails are the main power rails, whereas the 1.8V rail is only for logic interfacing with the MIPI CSI connector.

In the official design, 3.3V is supplied to the LT6911C through the CSI connector by the LicheeRV Nano. To prevent back feeding, the 3.3V pin on the CSI connector is left floating, and the ATX PSU's 3.3V rail supplied 3.3V to the LT6911C. The official design does not have any filtering for the 3.3V rail (other than decoupling capacitors), but the reference schematic passes the rail through a 120Ω@100MHz ferrite bead with 30mΩ DCR and 3A current rating before supplying the IC. Thus, a ferrite bead with matching impedence at 100MHz but lower DCR and higher current rating is used in this design. This bead was chosen because it was cheaper with (supposedly) better specifications.

Four 100nF decoupling capacitors are included on the 3.3V rail in the official 3D model, along with one single 10uF decoupling capacitor. As such, this design also uses these capacitor values and quantities for decoupling on the 3.3V rail.

The 1.2V rail is generated by the MCP1602 buck converter, which is fixed to supply 1.2V and max 500mA. Per the datasheet, the max 1.2V supply current used by the LT6911C is 306mA at 1080p 60Hz MIPI output (which is the maximum supported by the NanoKVM), which is within spec for the buck converter. The design of the MCP1602 circuit is the same as in the PS176 subsystem; it is essentially unchanged from Figure 6-3 in its datasheet.

Before being supplied to the LT6911C, the 1.2V rail passes through the same ferrite bead as the 3.3V rail. This matches the reference schematic and helps filter out high frequency noise on this rail.

In the official 3D model, four 100nF decoupling capacitors are included on the 1.2V rail, along with two 10uF decoupling capacitors. However, since the reference schematic uses six 100nF decoupling capacitors instead of four, this design uses six 100nF + two 10uF decoupling capacitors on the 1.2V rail.

To supply the 1.8V needed for the 1.8V logic of the MIPI CSI interface, a simple MCP1700 LDO is used to step down the 3.3V rail to 1.8V. This is not as efficient as a buck converter, but it uses a much smaller footprint, and the current supplied is very low anyways because the rail is only used for logic. The MCP1700T-1802E used in this design is fixed to 1.8V, and so only two 1uF capacitors (one on the input pin and one on the output pin, per the datasheet) are required.

### Crystal Oscillator
> *Pins: XTLI (64), XTLO (63)*

A 27MHz crystal oscillator is used in this subsystem to control timing. The datasheet does only mentions that a 27MHz, 100ppm crystal is needed (with no further elaboration), so this design decision is based on the 3D model. Below is a comparison table of the oscillator used in this design vs. the one used in the 3D model.

| LCSC Part Number | Used by:                | Load Capacitance | Frequency Stability | Frequency Tolerance | ESR |
| ---------------- | ----------------------- | ---------------- | ------------------- | ------------------- | --- |
| C255890          | 3D Model                | 8pF              | ±10ppm              | ±10ppm              | 60Ω |
| C37635384        | LAZARUS-1 Backplane PCB | 9pF              | ±10ppm              | ±10ppm              | 30Ω |

For frequency stability, frequency tolerance, and ESR, lower values are generally better. the oscillator used in this design is therefore a good choice. However, the load capacitance is not the same, and so different capacitor values are used.

> Note: the reference design uses 18pF capacitors, which seems far too high...? So 10pF capacitors are used in this design, which nets a stray board capacitance of 4pF.

### CSI I2C Pins
> *Pins: CSCL (21), CSDA (22)*

These pins form the I2C channel that connects to the I2C pins on the FPC connector. However, coming out of the LT6911C, they use 3.3V logic, whereas the Lichee RV Nano accepts 1.8V logic on the I2C pins of its FPC connector (per the official Lichee RV Nano schematic). As such, a level shifter is needed for these pins.

The level shifter used in this design is a simple enhancement MOSFET-based implementation that is [detailed here](https://www.digikey.ca/en/blog/logic-level-shifting-basics); in essence, the higher voltage logic (3.3V, from the LT6911C) is connected to the drain, the 1.8V LDO is connected to the gate, and the lower voltage logic (1.8V, to the CSI connector) is connected to the source. Pull up resistors to the respective logic voltages are included on the drain and source. This enables the system to abide by the following behaviour:

| Scenario                         | Gate voltage (LDO, 1.8V) | Drain voltage (3.3V I2C, LT6911C side)                                             | Source voltage (1.8V, CSI side)                              |
| -------------------------------- | ------------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Default state (no side asserted) | 1.8V                     | 3.3V (from pull up)                                                                | 1.8V (from pull up)                                          |
| Drain -> 0V                      | 1.8V                     | 0V                                                                                 | -> 0V (MOSFET internal diode opens, so source matches drain) |
| Source -> 0V                     | 1.8V                     | -> 0V (V_GS > V_th, so MOSFET turns on and current flows, so drain matches source) | 0V                                                           |

In effect, the logic on each side will match. This is essentially the same design as is used on the official NanoKVM Lite LT6911C board. However, in this design, this is accomplished with a 2 N-channel enhancement MOSFET ([EM6K7T2R](https://github.com/HynixCJR/serverv2_backplane/blob/main/datasheets/LT6911C_HDMI_to_CSI_system/ROHM_EM6K7T2R_Nch_MOSFET_datasheet.pdf)), as opposed to the official design, which uses a similar MOSFET ([DMN31D5UDJ](https://www.diodes.com/assets/Datasheets/DMN31D5UDJ.pdf)). The EM6K7T2R has the same max V_GS(th) of 1.0V (so the MOSFET should still turn on when the source is pulled low), but with lower R_DS(on) at 1.8V. However, the capacitance is higher (25pF vs. 22.6pF), but it should still be fine enough, as long as the FPC cable is short enough (which it will be, I think).

A 2kΩ pull up resistor is placed on the SCL/SDA lines on the LT6911C side, but the official design does not include them on the FPC side.
